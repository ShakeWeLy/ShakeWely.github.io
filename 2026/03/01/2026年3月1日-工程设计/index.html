2026年3月1日 工程设计

考虑是否需要设计base class

工厂模式

register

manager

工具方法位置,

format_messages是写在class llm合适还是class message 合适

  • 放到 Message 里会让模型层知道太多“上游协议细节”

一旦把 format_messages 放进 Message，Message 这个“领域对象”就被迫关心：

  • 怎么为某个具体 LLM 提供数据

  • 图像消息在这个 LLM 里的具体 JSON 结构

这会让 schema.py 变得沉重，也降低未来更换/增加 LLM 提供商时的灵活性。

让结构更清晰，可以：

  • 在 app/llm_message_formatter.py 或 app/utils/messages.py 做一个独立的 MessageFormatter（或函数），LLM 调用它即可。

  • 这样可以避免 LLM 类过大，同时也不会把协议适配逻辑塞进 Message。

但是没有必要 因为轻量

逻辑上属于 LLM 的一部分

动态更新

可以用self.system 来保存模板, 然后 system= 来进行动态更新和传入
