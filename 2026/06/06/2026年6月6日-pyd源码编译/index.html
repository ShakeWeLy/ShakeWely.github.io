1 生成 .pyd 的一般流程

Fairino SDK 的 setup.py 走的是 Cython 编译 路线：把 Robot.py 转成 C 代码，再编译成 Windows 扩展模块 .pyd。

整体链路

.pyd 不是单独“生成”的文件，而是 针对特定 Python 版本 + 平台 编译出来的二进制，所以 cp310 / cp312 不能混用。

实际操作步骤

1. 准备环境（在目标 conda 环境里做）

Windows 上还需要 C 编译器：

  • Python 3.12：需要 Visual Studio Build Tools（MSVC）
  • 官方注释里也写了 3.12 要加 --compiler=msvc

2. 进入源码目录

目录里必须有 Robot.py 和 setup.py（你当前目录里 Robot.py 已被删掉，编译前需要放回来）。

4. 编译产物

成功后在 fairino/ 下会看到：

文件 说明
Robot.cp312-win_amd64.pyd 最终可用的扩展模块
Robot.c Cython 生成的中间 C 文件（可删）
build/ 临时编译目录（可删）

5. 使用

Python 3.12 的注意点

注释里提到 3.12 可能需要改 setup.py：

因为 Python 3.12 移除了 distutils，继续用 from distutils.core import setup 可能报错。你仓库里自带的 Robot.cp312-win_amd64.pyd 说明官方已经用 3.12 编译过了，一般可以直接用，不必自己重编。

什么时候需要自己编译？

情况 是否需要自己编译
已有匹配版本的 .pyd（如 cp312） 不需要，直接用
Python 版本变了（3.10 → 3.12） 需要重新编译
修改了 Robot.py 源码 需要重新编译
从 Linux 换到 Windows 需要重新编译（平台不同）

和 pip install 的关系

setup.py 也可以用来安装到 site-packages：

这样会把 .pyd 装进 cvdet 的 site-packages/fairino/，之后任意脚本都能 from fairino import Robot，不必再写 sys.path。

一句话总结

生成 .pyd 的流程 = 在目标 Python 环境里安装 Cython + 编译器 → 进入 fairino/ → 运行 python setup.py build_ext --inplace → 得到对应版本的 Robot.cpXXX-win_amd64.pyd。

你现在的 cvdet（Python 3.12）已经有现成的 Robot.cp312-win_amd64.pyd，直接 import 即可；只有换 Python 版本或改源码时才需要重新走编译流程。

3 为啥编译后的 .pyd 几乎只对外暴露 RPC，CNDE_PKG 等内部类无法直接 import。, 哪里做了限制吗

结论：不是源码里做了“导出限制”

Robot.py 里没有 __all__、也没有 # cython: ... 之类的隐藏配置。
按 Cython 的默认规则，模块顶层的 class、def、常量都会进 Robot 模块的命名空间。

真正的原因是：你手里的 Robot.cp312-win_amd64.pyd 根本不是完整编译产物，而是一个约 35KB 的精简 stub。

证据对比

文件 大小 含 CNDE_PKG 含 GetSDKVersion 含 RobotState

windows/libfairino/Robot.cp310-win_amd64.pyd 4.2 MB ✅ ✅ ✅
windows/fairino/Robot.py 源码 662 KB ✅ ✅ ✅
