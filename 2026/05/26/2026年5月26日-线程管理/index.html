2026年5月26日 线程管理

线程（Thread）

线程是操作系统提供的最小执行调度单位之一，属于进程内部的执行流。

一个进程可以包含多个线程，这些线程共享进程的内存空间，由操作系统进行调度执行。

1. 线程的本质

线程可以理解为：

进程内部的一条执行路径

特点：

  • 由操作系统调度（OS scheduler）
  • 属于内核级并发（kernel-level concurrency）
  • 多线程可以在多核 CPU 上实现并行执行

2. 线程与进程的关系

  • 进程：资源分配单位（内存、文件句柄等）
  • 线程：执行单位（代码执行流）

一个进程中可以包含多个线程：

特点：

  • 线程共享进程内存
  • 线程之间通信简单（但也更容易出错）

3. Python 中的线程

Python 使用 threading 模块支持多线程：

说明：

  • start()：启动线程
  • join()：等待线程结束

4. 线程调度机制

线程由操作系统进行调度：

  • 抢占式调度（preemptive）
  • CPU 时间片轮转
  • 多线程可以“看起来同时运行”

5. Python 线程的限制（GIL）

Python 有一个重要限制：

GIL（Global Interpreter Lock，全局解释器锁）

影响：

  • 同一时刻只能有一个线程执行 Python 字节码
  • 多线程无法真正并行执行 CPU 计算

6. GIL 的影响

✔️ 适合场景（IO 密集）

  • 网络请求
  • 文件读写
  • 数据库操作

原因：

线程在 IO 阻塞时会释放 GIL

❌ 不适合场景（CPU 密集）

  • 图像处理
  • 深度学习计算
  • 大规模数值计算

原因：

线程无法真正并行执行 CPU 计算

7. 线程的优缺点

优点

  • 创建开销比进程小
  • 适合 IO 并发
  • 共享内存，通信方便

缺点

  • GIL 限制并行能力
  • 线程安全问题（竞争条件）
  • 调试复杂

8. 线程 vs 协程 vs 进程（核心对比）

模型 调度方式 并行能力 开销 适用场景
进程 OS调度 强（多核） 高 CPU密集
线程 OS调度 受GIL限制 中 IO并发
协程 用户态调度 无并行 极低 高并发IO

MainThread 在等谁？

_stream_processing_future 永远是最后一次 submit 的 Future：

  • 日志里的「停止处理帧」→ 往往是 先结束的那个（A）
  • result(5) 等的 → 最后一次 submit 对应的（常常是 B）

所以会出现：A 已经停了，API 还要等 5 秒。

小结表

问题 答案
A 结束后会马上触发 B 吗？ 会，只要池队列里还有下一次 submit(start_processing)
A 在哪销毁？ 不销毁对象；start_processing 因 is_processing=False 退出 while 并 return，Future_A 变 done
B 在哪启动？ 同一条 Stream 线程，A return 后线程池执行队列里下一个任务 → 再次进入 start_processing() 第 219 行
5 秒从哪来？ Main 对 最后一个 Future 做 result(timeout=5.0)，B 没被 stop，常等满超时

若要避免 B 被误启动，需要在 submit 前等待/取消未完成的 Future，并在 keyed 模式下用 Future 状态做防重，而不是只看 processor_thread。需要的话我可以按这个思路改 detector.py / biyi.py。
