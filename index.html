DETR

https://blog.csdn.net/baidu_36913330/article/details/120495817

DEtection TRansformer End-to-End Object Detection with Transformer

总体来说就是, 先通过resnet进行特征提取, 获取 [B, C, W, H] 转化为[B, L, D] 输入到transformer里, (其中, C=L, D由线性映射产生) , 输出的encoder 和 一个 query(不知道是啥, 好像是预设的检测个数[N, D])进行decoder, 最终decoder输出会经过两个线性层, 分别输出class 和 box位置,

1 模型架构

1.1 backbone

在 2020 年时候，还没有 Swin 这样的可以针对不同分辨率图像输入的 Transformer Backbone。目标检测的图一般比较大，那么直接上 Transformer 计算上吃不消，所以先用 CNN 进行特征提取并缩减尺寸，再使用 Transformer 是常规操作（或者说无奈之举）。

输入图片3×800×1066的一张图片，经过卷积神经网络提取特征，长宽32倍下采样后得到2048×25×34，然后通过一个1×1 Conv进行降维最终得到输出shape为256×25×34

1.2 位置编码

分 sin/cos 编码 和可学习编码

为了和特征完全匹配形状也为256×25×34，然后和特征进行元素级别的相加后输入到Transformer Encoder

采用xy方向分开的位置编码, 且xy分别各半个通道

1.3 Transformer Encoder

只是pos embed加在了attention前的qk上

1.4 Transformer Decoder

  1. pos embed加在了attention前的qk上
  2. 使用可学习的位置编码 Object Query
  3. object queries的维度设置为anchor数量×token维度。

Object Query

就是让模型先生成N=100个预测目标框, 最多只能识别100个个体

n个零向量, +可学习的位置编码

2 训练推理

2.1 匈牙利算法

防止同一物体可能被多个 query 抢

2.2 输出结构

DETR 把检测当成 集合预测：固定输出 N 个 query（比如 100)

  • query_embed：num_queries 个（常 100）
  • class_embed：num_classes + 1（多一类 no-object）
  • bbox_embed：输出 4 维框

3 结论

我看DETR和yolo有点像 都是cnn 作为backbone提取特征, 只是neck不一样, detr用transformer, yolo用级联, 特征融合等等, 最后是分类头

但是decoder 才是 DETR 的核心，它不是简单的"neck"，而是一个把"检测"建模成集合预测的模块, 最后用Query 集合预测 + 匈牙利匹配

DETR缺点在于：

（1）计算复杂度的限制导致不能利用大分辨率特征图，导致小目标性能差。

（2）注意力权重矩阵往往都很稀疏，DETR计算全部像素的注意力导致收敛速率慢。

  1. 提出多尺度可变形注意力模块, 不需要FPN.
  2. 为了降低计算量, 不需要image的所有位置进行注意力计算,而是只需和部分位置(学习而来的)进行交互.

DCN（Deformable Convolution Networks）：在卷积当中引入了学习空间几何形变的能力，不再是使用常规的领域矩阵卷积，而是让卷积自动的去学习需要需要卷积的周围像素，以此可以适应更加复杂的几何形变任务。

1 模型架构

1.1 backbone生成多尺度特征

多尺度的特征融合方法则是取了骨干网(ResNet)最后三层的特征图C3，C4，C5，并且用了一个Conv3x3 Stride2的卷积得到了一个C6构成了四层特征图, 并将通道数量统一为256, 最后将这4个不同尺度的特征送入transformer中的encoder中

1.2 多尺度位置编码

因为是四张图通level的特征图作为输入, 所以普通位置编码会有冲突, 因此添加了scale-level embedding 的变量, 就是在原始位置编码的基础上, 计算这个变量, 从而区分位置.

1.3 MSDeformAttn

普通 Transformer 的自注意力要让每个 token 和所有 token 两两计算，计算量随 token 数平方增长。多尺度图像有很多 token，这样做代价太高。

可变形注意力的做法是：每个 token 只在参考点附近采样少量位置（n_points=4），采样偏移量由网络学习得到，并且在 4 个尺度上各采样一次。

实现每一个Q和局部位置的K和V进行计算, 而不是全局

因此要解决的问题就是：（1）确定reference point。（2）确定每个reference point的偏移量(offset)。（3）确定注意力权重矩阵

采用了金字塔特征进行transformer的输入, 并使用anchor和可生成Q, 以及一些训练策略加速手链

1. 模型结构

2. Query selection

从编码器输出的所有位置里，挑出得分最高的一批位置，把它们作为解码器的初始查询（object query）

原始 DETR 的查询是一组随机初始化、与图像无关的可学习向量，解码器要从零开始学习"该去哪里找目标"，收敛慢。

让编码器先对每个位置做一次粗略的"有没有目标、框在哪"的预测，然后把最可能是目标的位置直接交给解码器，从更好的起点开始。

首先 为 5440 (特征图总和)个位置都生成一个框, 不同尺度的框大小不同。对所有的特征输入到一个线性层, 输出由dim->class_num, 并进行topK排序, 从5440中选出900个预选位置

(bs, 5440, 256) --> (bs, 5440, 91)

3. CDN（Contrastive DeNoising，对比去噪训练

在训练时额外加入的一组辅助查询。它不参与推理，只为训练提供更稳定、更直接的监督信号。

思路是：在训练时，直接把真实框加噪声作为输入，让一部分查询去"还原"对应的真实框。这些查询的对应关系是已知的，不需要匹配，因此监督信号更稳定、收敛更快。通过同时添加同一真实标签的正负样本来训练模型，避免模型对同一目标的重复输出（也就是把真实标签重复多组，一组中分为positive和negative两部分）

D-FINE

**D-FINE：**将 DETR 中的回归任务重新定义为细粒度分布细化。D-FINE重新定义 DETR 模型中的边界框回归任务，实现了卓越的定位精度。D-FINE 包含两个核心组件：细粒度分布细化（Fine-grained Distribution Refinement, FDR）和全局最优定位自蒸馏（Global Optimal Localization Self-Distillation, GO-LSD）。FDR 将回归过程从预测固定坐标转变为迭代地细化概率分布，提供了一种细粒度的中间表示，显著提升了定位精度。GO-LSD 是一种双向优化策略，通过自蒸馏将来自精细化分布的定位知识传递到较浅层，同时简化了深层网络的残差预测任务。

5 L2正则化

是什么
是一种模型训练时防止过拟合的手段, 主要是通过给梯度添加限制来实现, 从而减少loss的数值下降太快

在loss函数里, 加一项权重的平方和, 以此来惩罚过大的权重

∗L∗=∗L∗data+2∗λ∗∗i∗∑∗w∗∗i∗2*L*=*L*data+2*λ**i*∑*w**i*2 ∗L∗=∗L∗data+2∗λ∗∗i∗∑∗w∗∗i∗2

这样就能实现对权重进行缩放

梯度dl/dw = dy/dw + aw -> w = w -r(dl/dw) => w = w(1-ar) - r*dy/dw

为什么
正常的梯度下降公式w = w - lr x dt
添加L2正则化后, 会给dt 做限制, 显示通过一个参数a: 使得dt = dt + a x dt

  1. 权重大容易记住噪声🤔

  2. 权重小票-> 函数平滑 -> 泛化更好

    因为权重数值大, 跳跃就大, 会导致优化方向波动大, 难优化

    权重大小直接决定了：

    输入变一点，输出会变多少。

    • w 很大 → 输入稍微变一点，输出剧烈变化 → 函数陡峭、敏感
    • w 很小 → 输入变一点，输出变化很小 → 函数平缓、平滑

用在哪?
用在loss函数里, 减缓loss只下降过快

6 L1正则化

是什么

给loss加w --> 梯度而外加一个符号函数, 使得大于0的+1, 小于0的-1(后面会乘上一个λ)

为什么

  • 当 w>0，梯度里多一个 +λ，每次更新都往 0 推 ηλ (减去)
  • 当 w<0，梯度里多一个 −λ，每次更新也往 0 推 ηλ

用在哪🤔

  • 特征选择：稀疏权重意味着很多特征被完全忽略
  • 高维稀疏数据：比如文本分类，特征几万维，L1 能选出少数重要特征
  • 可解释性要求高：想知道哪些特征真正有用

The num_workers 参数控制用于数据加载的子进程数量。这对于并行化高开销的数据变换至关重要。

工作原理

  • 每个工作进程都维护一个批次队列（由 prefetch_factor 控制）
  • 工作进程并行准备批次，并将其传输给主进程
  • 如果 in_order=True（默认），批次将按顺序返回

何时增加 num_workers

  • 当变换的计算开销很大时（如数据增强、解码）
  • 当数据从慢速存储器（网络驱动器、机械硬盘）加载时
  • 当您观察到由于数据加载导致的 GPU 闲置时间时

何时 num_workers=0 可能会更快

  • 当变换的开销很低时（如简单的张量操作）
  • 当数据已经存在于内存中时
  • 进程间通信 (IPC) 的开销超过了并行化的收益

理解 pin_memory

The pin_memory 参数通过使用锁页（pinned）内存来实现更快的 CPU 到 GPU 数据传输。

最佳实践

  1. 在 DataLoader 中使用 pin_memory=True（推荐方法）
  2. 在将数据移动 to GPU 时结合使用 non_blocking=True
  3. 避免手动调用 tensor.pin_memory() 接着调用 .to(device, non_blocking=True) - 这样更慢，因为 pin_memory() 是阻塞的

持久化工作进程 (Persistent Workers)

默认情况下，工作进程会在不同的 epoch 之间关闭并重新启动。这会在每个 epoch 边界上引入启动开销（导入模块、分支进程、重新初始化数据集）。

将 persistent_workers=True 设置为 True 可以使工作进程在多个 epoch 之间保持活动状态，从而消除重复的启动成本。

在什么情况下最有效

  • 在较小的数据集上训练许多 epoch
  • 当数据集 __init__ 开销很大时（例如加载元数据）
  • 当与较高的 num_workers 结合使用时

Dropout

共适应（Co-adaptation）

是指在深度神经网络中，某些神经元过度依赖其他特定的神经元来共同完成特征提取，导致它们“绑定”在一起工作，无法独立发挥作用的现象。

你可以把它理解为“团队里的依赖症”或“抱团偷懒”。

1. 为什么会出现共适应？

神经网络本质上是通过梯度下降来“找捷径”的。如果在训练过程中没有任何干预：

  • 神经元 A 学习到了一个非常强的特征（比如识别狗的耳朵）。
  • 神经元 B 发现：“只要我每次都顺着 A 的输出做微调，就能把 Loss 降下去，那我干脆不用自己去学新特征了。”
  • 结果：B 变成了 A 的附庸。B 并没有学会独立识别“狗的眼睛”或“狗的鼻子”，它只是学会了“如何纠正 A 的微调误差”。

一旦进入测试阶段，输入的图片稍微有些噪点，导致神经元 A 识别失误，依赖 A 的神经元 B 会瞬间跟着崩溃，整个网络的泛化能力大幅下降（即产生了过拟合）。

3. Dropout 是如何消除共适应的？

正如你引用的这段话所描述的：

  • 在训练期间，以概率 ppp 随机将输入张量中的一些元素归零。
  • 在每次前向传播调用中，被清零的元素都是独立选择的。

当 Dropout 随机把某些神经元的输出清零（杀掉）时：

  1. 阻断依赖链条： 神经元 B 无法预测每一个 Step 神经元 A 是否还在。它不能再寄希望于“抱 A 的大腿”，必须自己学习具备独立表达能力的特征。
  2. 解耦特征组合： 迫使网络中的每一个神经元与周围不同的神经元随机组合（Form randomized ensembles）。每个神经元都被要求在各种不同的“残缺上下文”中都能正常工作。

1 CSM

交叉扫描模块（Cross-Scan Module，CSM）。我们选择沿行和列展开图像补丁成序列（扫描扩展），然后沿四个不同方向进行扫描：从左上到右下，从右下到左上，从右上到左下，从左下到右上。这样，任何像素（如图 2 中的中心像素）都会从不同方向的所有其他像素中集成信息。然后，我们将每个序列重新整形成单个图像

这个模块主要代替了Transformer中的注意力机制，在保留全局感知的情况下保持了线性的计算复杂度。

1. SSM 天然是 1D 因果的

单向扫描时，像素 A 能影响 B，但 B 影响不了 A（取决于谁先谁后）。单方向会有 方向偏差——左上影响右下，反之不行。

2. 四向 = 从四个方向聚合上下文

单向 HW： 像素 15 能看到 ← 左边、上边来的信息

反向 HW： 像素 15 能看到 → 右边、下边来的信息

WH + 反向 WH：补上「列方向」的上下左
